# Agent落地计划

既然你已经跨过了基础概念的门槛，接下来的核心目标就是**从“理论”走向“工程落地”**。掌握 Agent 的关键不在于背诵原理，而在于理解**状态机、工具调用、记忆持久化以及多 Agent 协同**的工程实现。

这里为你量身定制了一条**从单体到分布式、从微调到编排**的进阶学习路线，带你攻克主流框架与实战项目。

## 阶段一：从零手写，吃透核心底层（预计 1 周）

在急于使用 LangChain 或 AutoGen 等重型框架之前，建议先用原生 Python（或结合 OpenAI/Anthropic SDK）**手写一个闭环 Agent**。这样你能清晰看到框架底层到底帮你封装了什么。

### 核心学习点

- **ReAct 模式手写实现**：不用任何框架，仅依靠 Prompt 提示词，让 LLM 输出 `Thought -> Action -> Observation -> Thought` 的循环。
- **原生 Function Calling（工具调用）**：理解大模型如何输出 JSON 结构化数据，你如何在本地解析该 JSON、执行本地函数（如查询数据库/API），并将结果塞回 Chat History。
- **状态与记忆管理**：手写一个 Token 计数器，当对话历史超过 Context Window 时，实现**滑动窗口截断**或**摘要压缩（Summary Memory）**。

### 实战项目

> **项目：轻量级本地数据分析 Agent**
>
> - **功能**：给 Agent 绑定两三个本地工具（如 `read_csv`, `calculate_mean`, `plot_chart`）。
> - **目标**：输入“帮我分析这份销售数据并画出趋势图”，Agent 能自主思考、多次调用工具并完成任务。

## 2. 阶段二：主流单兵框架进阶（预计 2-3 周）

当手写项目让你感到“在重复造轮子”时，就是引入框架的最佳时机。目前生产环境（尤其是企业级应用）最推崇的是基于图结构（Graph-based）的框架，因为它能提供极高的控制力。

### 核心攻关框架

- **LangGraph (强烈推荐)**：LangChain 家族目前最核心的资产。它将 Agent 抽象为**状态图（StateGraph）**。你必须掌握：
  - `State`（状态定义与传递）
  - `Nodes`（执行动作，如调用 LLM 或工具）
  - `Edges / Conditional Edges`（根据 LLM 输出决定下一步走哪个分支）
- **LlamaIndex (Workflows)**：如果你的 Agent 强依赖于海量私有数据的检索（RAG），它的工作流机制非常适合构建知识密集型 Agent。

### 核心学习点

- **确定性与非确定性的平衡**：如何用代码逻辑（硬编码的图分支）去规范大模型的自由发挥，防止 Agent 陷入死循环。
- **Human-in-the-loop (人工介入)**：如何在 Agent 准备执行高危操作（如扣款、删除数据、发送邮件）时，暂停状态图，等待人工确认（Approve）后再继续。

### 实战项目

> **项目：智能文献/技术文档精读与报告生成器**
>
> - **功能**：用户输入一个主题，Agent 先去检索多篇长文档（RAG），提取核心观点，发现矛盾点，补充缺失信息，最后生成一份排版精美的 Markdown 报告。
> - **技术栈**：LangGraph + 向量数据库 + 动态路由。

## 3. 阶段三：多 Agent 协同与分布式编排（预计 2 周）

现实中的复杂任务，靠一个 Agent 往往会因为 Prompt 太长或职责太多而“脑干缺失”。这时需要演进为**多 Agent 团队（Multi-Agent System）**。

### 核心攻关框架

- **CrewAI**：目前上手最快、角色扮演（Role-playing）最成熟的框架。非常适合流程明确的流水线任务（如：调研、写稿、校对、排版）。
- **Microsoft AutoGen**：基于**事件驱动**和**对话式**的多 Agent 框架。适合构建复杂的、非线性的、 Agent 之间能自由拉群聊天的复杂场景。

### 核心学习点

- **通信拓扑结构**：理解星型拓扑（一个 Manager 调度多个 Worker）、流水线拓扑（A 做完给 B，B 做完给 C）和自由对话拓扑的区别。
- **SOP（标准作业程序）的数字化**：如何把现实中人类团队的工作流程，映射为多个 Agent 的 Prompt 和协作关系。

### 实战项目

> **项目：全自动软件需求分析与架构设计团队**
>
> - **角色配置**：
>   1. `Product Manager Agent`：负责澄清用户模糊的需求，输出 PRD。
>   2. `Software Architect Agent`：根据 PRD 设计模块架构，输出 UML 类图或组件描述。
>   3. `Code Reviewer Agent`：评审方案可行性。
> - **目标**：输入一句话需求，三者自动开会讨论，最终交付一份完整的技术方案设计书。

## 4. 阶段四：前沿协议与工程落地（高级进阶）

当框架用熟之后，你会发现工具的接入和数据安全才是真正的痛点。这一阶段关注行业最新标准。

### 核心学习点

- **MCP (Model Context Protocol)**：由 Anthropic 推出的全新开放标准。它改变了“为每个框架写一套 Tool”的现状。
  - **核心逻辑**：解耦客户端和服务器。你只需要写一个 MCP Server（连接你的本地数据库、GitHub、企业内部系统），任何支持 MCP 的客户端（如 Claude Desktop、Cursor 或是你自己的 Agent 框架）都能直接调用这些工具和上下文。
- **Agent 的持久化与可观测性**：
  - **LangSmith / Phoenix**：如何监控 Agent 走过的每一步 Graph 轨迹，分析哪一步消耗了最多 Token，哪里出现了幻觉。
  - **安全与隐私隔离**：如何在本地或专有云部署 Agent，确保敏感数据（如用户隐私、企业资产）在调用外部 LLM API 时做脱敏或本地拦截。

## 💡 给你的路线避坑建议

1. **不要迷失在 LangChain 庞大的生态里**：LangChain 早期版本的经典链（LLMChain, RetrievalQA）已经过时，直接从 **LCEL（LangChain 表达式语言）** 和 **LangGraph** 切入。
2. **死磕“稳定性”**：写完 Agent 后，测试时不要只测一次。用同一套输入跑 20 次，看它有多少次会跑偏、多少次会死循环。解决这 20% 的不确定性，才是工程的核心价值。
3. **关注小模型 Tool-using 能力**：尝试用一些本地开源模型（如 Llama 3.1, Qwen 2.5）来跑你的 Agent。学会如何在有限的算力下通过精简 Prompt 让小模型也能稳定输出 Function Calling 要求的 JSON。

你可以先从**阶段一的手写 ReAct 闭环**开始，大概只需要一两个晚上的时间，就能让你对 Agent 的底座建立极强的工程体感。在这个过程中有任何关于代码架构或逻辑走不通的地方，随时找我拆解。
