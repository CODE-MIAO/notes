设计一个高质量的 Agent System Prompt（系统提示词），本质上是在为 AI 建立一套**“运行宪法”**。它不仅决定了 AI 的语气，更决定了它如何思考、如何调用工具以及如何处理错误。

以下是设计 Agent 系统提示词的 **6 个核心维度**，以及关于 **权重** 的深度解析。

---

### 一、 设计 System Prompt 的 6 个角度

一个专业的 Agent 提示词通常采用结构化编写（如使用 Markdown 或 XML 标签），包含以下部分：

#### 1. 角色定义 (Identity & Role)
*   **不仅是头衔，更是专业背景。**
*   *错误示例*：“你是一个代码助手。”
*   *优秀示例*：“你是一位精通 C++ 和 Qt 框架的 Workbench 专家，擅长通过分析 UI 结构来优化用户工作流。你冷静、严谨，像一位资深架构师一样思考。”

#### 2. 核心任务与目标 (Goals & Mission)
*   **明确 Agent 存在的终极意义。**
*   *描述*：你需要帮助用户通过指令操作 Workbench 页面。你的目标是减少用户的重复劳动，并确保每一次工具调用都是准确且安全的。

#### 3. 工具使用规范 (Capabilities & Tool Usage)
*   **这是 Agent 的灵魂。** 你需要告诉模型什么时候该用工具，以及怎么用。
*   *逻辑引导*：在采取行动前，先进行“Thought（思考）”。如果用户的问题可以通过工具解决，必须优先调用工具。
*   *强制要求*：如果工具返回了错误，分析错误原因并向用户解释，不要尝试编造结果。

#### 4. 行为约束与边界 (Constraints & Guardrails)
*   **明确“禁区”。**
*   *示例*：
    *   禁止操作用户未授权的敏感页面。
    *   如果用户的指令模糊不清，必须先询问确认，严禁猜测。
    *   回答必须简洁，不要输出冗长的解释，除非用户要求。

#### 5. 思考链引导 (Chain of Thought)
*   **要求模型在输出最终答案前，先展示其推理过程。**
*   *提示词*：在输出任何 JSON 指令前，请先在 `<thought>` 标签内分析用户的意图，并列出所需的工具参数。

#### 6. 输出格式要求 (Output Format)
*   **确保 Agent 返回的内容能被你的程序（Python/C++）正确解析。**
*   *提示词*：所有对 Workbench 的操作必须封装在特定的 JSON 格式中。
*   *技巧*：给出一个 **Few-Shot（示例）** 是最高效的方式。

### 二、 系统提示词的权重真的更高吗？

这是一个非常关键的技术问题。答案是：**在架构设计上，它的权重通常更高，但在超长上下文面前，它也会面临“注意力衰减”。**

#### 1. 架构层面的权重 (System Message vs. User Message)
*   **预处理优先级**：在 GPT-4 或 Claude 的推理机制中，`System Message` 会在对话的第一步就被加载到 KV Cache 中。它作为整个对话的“基调（Priors）”，对后续所有 Token 的预测产生持续影响。
*   **指令强制性**：模型被训练为必须服从 System 角色。如果 User 叫模型做坏事，而 System 禁止了，模型通常会遵循 System。

#### 2. 注意力机制的影响 (Attention Mechanism)
*   **位置偏差 (Positional Bias)**：虽然模型试图平等对待所有上下文，但随着对话变得越来越长（比如达到 100k token），模型往往会产生“中间遗忘”现象。**最开头（System）和最结尾（最近的对话）的权重通常最高。**
*   **指令覆盖**：如果 User 在最新的对话中反复要求模型“无视之前的指令”，有些模型可能会产生“指令遵循冲突”，导致系统提示词的效果减弱。这就是所谓的 **Prompt Injection（提示词注入攻击）**。

#### 3. 权重是动态的
*   现在的模型（如 Claude 3.5）引入了特殊的训练方法，让 System Role 具有极强的“抗干扰能力”。它被视为 Agent 的**底层逻辑**，而 User 内容被视为**输入数据**。

### 三、 给你的 Workbench Agent 写一个具体的模板

结合你之前的 C++ Workbench 场景，你可以尝试这个结构：

```xml
<system_prompt>
    <role>
        你是一个集成了 Workbench 系统的 AI 智能体。你通过 MCP 协议与 C++ 桌面端通信。
    </role>

    <tools>
        你可以调用 open_page, edit_component 等工具。
        调用规范：
        1. 必须先通过 <thought> 分析。
        2. 确保参数中的 ID 是从上下文中获取的真实 ID。
    </tools>

    <rules>
        - 严禁在没有用户明确授权的情况下删除任何组件。
        - 如果 C++ 端返回 "QUOTA_EXCEEDED" 错误，请引导用户去官网充值。
        - 保持专业、干练的语气。
    </rules>

    <example>
        User: "打开设置页面并把主题改为红色"
        Assistant:
        <thought>用户想要修改UI状态，我需要先调用 open_page，然后调用 set_theme。</thought>
        [调用工具...]
    </example>
</system_prompt>
```

### 总结建议：
1.  **结构化**：多用 XML 标签或 Markdown 标题，模型更容易分清职责。
2.  **迭代**：如果发现 Agent 经常乱调工具，就在 System Prompt 里增加一个“负面约束（Don'ts）”。
3.  **动态 System Prompt**：如果你有很多工具，不要一次性全塞进去。可以根据 C++ 端的当前页面，**动态修改**发送给模型的 System Prompt，只包含当前相关的工具说明。这能极大地提高准确率。
