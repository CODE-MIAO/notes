这两个 Model Context Protocol (MCP) 服务看起来很相似，但它们的**工作原理**、**作用范围**以及**运行载体**有本质的区别。

以下是为你整理的详细对比和原因分析：

## 1. 这两个 MCP 有什么区别？

| **特性**     | **Figma Desktop (上方)**                                     | **figma (下方 - Plugin MCP)**                                |
| ------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **运行载体** | 运行在你**本地电脑的 Figma 桌面客户端**中。                  | 运行在 **Cursor 编辑器内部**（通过其内置的插件生态）。       |
| **连接机制** | Cursor 作为一个客户端，去连接本地正在运行的 Figma 软件开放的本地端口。 | Cursor 直接运行该集成，通常是通过官方的 API 远程获取数据。   |
| **能力差异** | 拥有 5 个工具、3 个 prompt，专注于**本地上下文**和实时编辑器交互。 | 拥有 18 个工具、1 个 prompt、34 个资源，功能更全面（支持更多的远程数据和结构读取）。 |

## 2. 为什么在图 2 关闭后，下面的 MCP 依然有效？

你在图 2 中勾选/取消勾选的 **"Enable desktop MCP server"** 是 **Figma 桌面客户端**内部的一个开关。

- **对于上面的 MCP (`Figma Desktop`)**：它的生命线就在 Figma 客户端里。当你关闭了图 2 的开关，Figma 客户端就**停止了本地 MCP 服务器的运行**。Cursor 连不上它了，所以它显示为 `0 tools, 0 resources`。
- **对于下面的 MCP (`figma`)**：它是一个 **Plugin MCP Server**（注意它属于 "Plugin MCP Servers" 分组）。它的运行**完全不需要依赖你本地的 Figma 桌面软件**。它是 Cursor 直接通过网络与 Figma 的云端服务器（通过 API 密钥或 OAuth 登录）进行通信的。所以，即使你把本地 Figma 软件关闭或者把图 2 的开关取消，这个插件依然能正常读取到云端的工具和资源。

## 3. 它们是怎么实现 Login 和 Logout 的？

MCP 规范本身不仅支持传输数据，还允许定义**自定义动作（Tools/Actions）**。

- **Figma Desktop (本地认证)：** 当你点击 `Login` 时，Cursor 会向本地的 Figma 软件发送一个请求，Figma 软件会弹出标准的 OAuth 授权网页，或者直接复用你已经在桌面端登录好的 Session（ Token 存储在本地安全的 Keychain 或凭据管理器中）。点击 `Logout` 则是在本地清除该连接的 Access Token。

- **Plugin figma (云端/浏览器认证)：**

  这个是由 Cursor 插件发起的。点击 `Login` 时，Cursor 会弹出一个内置窗口或跳转到浏览器，让你登录 Figma 账号并授权给 Cursor。授权成功后，Figma 会返回一个访问令牌（Token），Cursor 会将其**加密存储在本地的编辑器配置/缓存中**。点击 `Logout` 时，Cursor 就会从本地配置文件中彻底删掉这个 Token，从而断开连接。

### 💡 建议

如果你平时习惯开着 Figma 客户端画图，希望 AI 能够秒级感知到你当前选中的图层，用上面的 **Figma Desktop** 体验更好；如果你只是希望 AI 能根据一个 Figma 链接去读取设计稿，不用管本地开没开软件，用下面的 **Plugin figma** 更稳定、功能也更全。
