# UV

简单来说，**`uv` 是一个用 Rust 编写的、速度极快的 Python 包管理和项目管理工具**。

它是由 Astral 公司（就是开发了超火的 Python 代码检查工具 `ruff` 的那个团队）开发的。它的目标是替代现有的 `pip`、`pip-tools`、`poetry`、`pipenv` 以及 `virtualenv` 等一系列工具，成为 **Python 生态中的“万能工具箱”**。

如果你用过 Node.js 生态，`uv` 的定位和体验非常类似于 **`pnpm`** 或 **`bun`**。

## 为什么 `uv` 最近这么火？

### 1. 极致的速度（快得离谱）

这是 `uv` 最硬核的卖点。因为是用 Rust 写的，它比传统的 `pip` 快了大约 **10 到 100 倍**。

- 它有先进的缓存机制。
- 即使在没有缓存的情况下，它的依赖解析算法也极其高效。
- 在本地冷启动创建虚拟环境只需要几毫秒，安装万级依赖也只需几秒钟。

### 2. 它是“多合一”的超级工具

以前你在开发 Python 项目时，可能需要安装一堆工具：用 `pyenv` 管理 Python 版本，用 `virtualenv` 创建虚拟环境，用 `pip` 安装包，用 `poetry` 管理项目依赖。

现在，**一个 `uv` 就能搞定以上所有事情**。

## `uv` 的核心功能与常用命令

`uv` 的设计非常贴心，它的命令分为两大类：**兼容 pip 的底层命令** 和 **现代化项目管理命令**。

### ① 替代 `pip` 和 `virtualenv`（底层命令）

如果你不想改变现有的工作流，只想体验极致的加速，可以直接用它代替旧工具：

- **创建虚拟环境**：

  Bash

  ```
  uv venv
  ```

  *(一眨眼的功夫就创建好了 `.venv` 目录)*

- **安装 Python 包**：

  Bash

  ```
  uv pip install requests
  ```

  *(速度比 `pip install` 快几个量级)*

- **编译依赖（类似 pip-compile）**：

  Bash

  ```
  uv pip compile requirements.in -o requirements.txt
  ```

### ② 现代化项目管理（类似 Poetry / Cargo）

这是 `uv` 后来引入的更高级的功能，让 Python 的开发体验向 Rust 的 `cargo` 看齐。

- **自动管理 Python 版本**：

  你甚至不需要提前在电脑上安装 Python！当你运行 `uv python install 3.12` 时，它会自动下载并管理指定的 Python 版本。

- **创建和管理项目**：

  Bash

  ```
  uv init my-project
  ```

  它会帮你生成一个包含 `pyproject.toml` 的标准现代化项目结构。

- **运行脚本（自动处理依赖）**：

  这是一个超级强大的功能。如果你有一个单独的脚本 `script.py`，里面用了 `requests` 库，你不需要手动创建虚拟环境安装它，直接运行：

  Bash

  ```
  uv run script.py
  ```

  `uv` 会在后台自动创建一个临时环境，下载好依赖并运行脚本，用完即焚，非常干净。

## 总结

> **用一句话概括：**
>
> `uv` 是目前 Python 社区最受瞩目的“下一代”包管理工具。它用 Rust 的惊人速度和现代化的多合一设计，正在逐步终结 Python 过去混乱、缓慢的包管理历史。

如果你经常饱受 `pip install` 慢、虚拟环境配置繁琐的折磨，强烈建议你尝试一下 `uv`，体验绝对是颠覆性的。



# UV初始化项目结构

看到这个目录结构，说明你成功使用了 `uv init` 命令。这是一个非常标准、优雅的**现代化 Python 项目结构**（符合 PEP 621 标准）。

我们来逐一拆解这些文件和文件夹，看看它们各自扮演了什么角色：

### 1. `pyproject.toml` （核心配置文件）

- **它是干什么的**：这是你整个项目的“大脑”。以前 Python 项目习惯用 `requirements.txt`、`setup.py` 或 `setup.cfg`，现在现代 Python 社区统一推荐使用 `pyproject.toml`。
- **里面有什么**：如果你用记事本打开它，会看到：
  - **项目元数据**：项目名字、版本号、作者信息、开源协议等。
  - **Python 版本限制**：声明这个项目需要什么版本的 Python（例如 `requires-python = ">=3.12"`）。
  - **项目依赖列表**：以后你运行 `uv add requests` 时，第三方库的名字和版本要求会自动记录在这里。

### 2. `.python-version` （Python 版本锁定文件）

- **它是干什么的**：它是给 `uv` 自己（以及 `pyenv` 等工具）看的，用来**明确指定当前项目应该使用哪个精确的 Python 版本**（比如 `3.12.3`）。
- **有什么妙用**：当你在该目录下运行 `uv run` 或 `uv venv` 时，`uv` 会自动读取这个文件。如果它发现你电脑上没有这个版本的 Python，它会**在后台默默帮你下载好**，完全不需要你手动去官网或者用 Conda 下载。

### 3. `main.py` （代码入口）

- **它是干什么的**：这是 `uv` 贴心地为你生成的默认业务代码文件。
- **怎么用**：目前里面应该只有一行简单的 `print("Hello from xxx")`。它是你项目的起点，你可以直接在这个文件里开始编写你的 Python 业务逻辑。

### 4. `README.md` （项目说明文档）

- **它是干什么的**：标准的 Markdown 格式说明文件。
- **有什么用**：用来用文字记录这个项目是干嘛的、怎么运行、怎么配置。当你把项目上传到 GitHub 或者 GitLab 时，这个文件的内容会直接显示在项目的主页上。

### 5. `.git` & `.gitignore` （版本控制组件）

- **`.git`（隐藏文件夹）**：这是 Git 仓库的本地数据库，用来记录你代码的每一次修改历史（代码版本的“后悔药”）。
- **`.gitignore`（文本文件）**：用来告诉 Git **哪些文件不需要被上传/追踪**。`uv` 默认在里面帮你写好了规则，比如以后自动生成的虚拟环境目录 `.venv`、缓存目录 `.uv`、二进制编译垃圾文件（`.pyc`）等，都不会被错误地提交到 Git 仓库里。

## 💡 接下来你该怎么做？

既然项目已经初始化好了，你可以直接在当前目录下打开终端，体验以下几个最常用的 `uv` 现代化命令：

1. **添加一个依赖（比如安装 requests 库）**：

   Bash

   ```
   uv add requests
   ```

   *运行后，你会发现 `pyproject.toml` 里多了一行依赖，并且目录下自动生成了一个 `.venv`（虚拟环境）和一个 `uv.lock`（锁定全部间接依赖版本的神级文件）。*

2. **直接运行你的代码**：

   Bash

   ```
   uv run main.py
   ```

   *`uv` 会自动检查 `.venv` 环境，确保所有依赖和 Python 版本正确，然后瞬间执行你的代码。*
